# Contributing

Thanks for working on the AI Student Assistant! A few quick notes to keep the codebase tidy.

## Setup

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env  # then fill in your keys
```

## Branching

- `main` — stable, demo-ready
- `dev` — integration branch
- `feature/<short-name>` — your work

Open a PR from your feature branch into `dev`. Merge `dev` into `main` for releases or demo checkpoints.

## Code style

- Format with `black src/ scripts/ tests/`
- Lint with `ruff check src/ scripts/ tests/`
- Type hints encouraged on public functions
- Docstrings on any function used across modules

## Tests

Add tests under `tests/` for new modules. Run with:

```bash
pytest tests/
```

## Commit messages

Short, imperative, present tense:

- ✅ `add reranker fallback when bge model unavailable`
- ❌ `Added some changes to the retriever stuff`

## Don't commit

- `.env` (real keys)
- `data/chroma/` (regenerated by `scripts/build_index.py`)
- `data/uploads/` (runtime artifacts)
- `logs/` (trace logs)
- `__pycache__/`, `*.pyc`

These are already in `.gitignore`.

## Adding a new prompt

Prompts live under `prompts/en/` and `prompts/ar/`. Keep the two language versions in sync — same filename, same variables.

## Adding a new dependency

Pin it in `requirements.txt`. The Gradio/FastAPI stack is version-locked because the components break on minor version drift; check before bumping any of those.
